# Cybersecurity Metrics and Key Risk Indicators (KRI)

## Overview

Cybersecurity metrics are measurements used to determine how well an organization's security program is performing.

Metrics help security teams:

- Measure security performance
- Identify weaknesses
- Track improvements
- Support decision-making
- Communicate security information to management
- Identify and monitor risks

A good metric should provide useful information that can support a security decision.

---

## What Is a Cybersecurity Metric?

A cybersecurity metric is a measurable value used to evaluate some aspect of cybersecurity.

### Examples

- Number of security incidents
- Number of failed login attempts
- Percentage of systems with current security patches
- Average time to detect an incident
- Average time to respond to an incident
- Number of employees who completed security training
- Percentage of systems protected by endpoint security

### Example

An organization discovers that:

> 95% of its computers have the latest security updates installed.

The 95% value is a cybersecurity metric.

---

# Key Performance Indicators (KPIs)

A **Key Performance Indicator (KPI)** is a measurement used to determine how effectively an organization is achieving a specific goal.

KPIs focus on **performance**.

### Cybersecurity KPI Examples

- Percentage of employees who complete security training
- Percentage of systems successfully backed up
- Average time to resolve security incidents
- Percentage of critical vulnerabilities patched within the required timeframe

### Example

Security goal:

> Patch critical vulnerabilities within 14 days.

KPI:

> Percentage of critical vulnerabilities patched within 14 days.

A KPI helps determine whether the organization is meeting its security goal.

---

# Key Risk Indicators (KRIs)

A **Key Risk Indicator (KRI)** is a measurement that helps identify or monitor changes in risk.

KRIs focus on **risk**.

They can provide an early warning that an organization may be becoming more exposed to a security threat.

### Examples

- Number of critical vulnerabilities
- Number of systems running unsupported software
- Number of failed authentication attempts
- Number of high-risk security findings
- Percentage of employees who fail phishing-awareness tests
- Number of third-party vendors with unresolved security issues

---

# KPI vs. KRI

| KPI | KRI |
|---|---|
| Measures performance | Measures risk |
| Shows whether goals are being achieved | Shows changes in risk exposure |
| Focuses on effectiveness | Focuses on potential problems |
| Often measures progress toward a goal | Often provides an early warning |
| Example: 95% of systems patched on time | Example: 50 critical vulnerabilities remain unpatched |

### Easy way to remember

**KPI = Performance**

**KRI = Risk**

---

# Security Metrics and Management

Security metrics can help communicate technical security information to management.

Management may not need to know every technical detail.

Instead of saying:

> "We have 4,500 vulnerability scan findings."

A security team might report:

> "Critical vulnerabilities increased by 20% this quarter."

This makes the information easier to understand and can help management make decisions.

---

# Leading and Lagging Indicators

Security measurements can also be categorized as **leading indicators** or **lagging indicators**.

## Leading Indicator

A leading indicator can provide information about what **may happen in the future**.

It can help identify potential problems before they become incidents.

### Examples

- Number of unpatched critical vulnerabilities
- Percentage of employees who fail security-awareness tests
- Number of systems using unsupported software
- Number of high-risk vulnerabilities discovered

### Memory Trick

**Leading = Warning**

It can warn you about a potential future problem.

---

## Lagging Indicator

A lagging indicator measures something that **has already happened**.

### Examples

- Number of security incidents last month
- Number of compromised accounts
- Amount of data affected by an incident
- Number of successful phishing attacks

### Memory Trick

**Lagging = Look back**

It measures results or events that have already occurred.

---

# Baselines

A **baseline** is a normal or expected level of activity used for comparison.

Baselines help security teams identify unusual changes.

### Example

Normally, a server receives approximately:

> 1,000 login attempts per day.

Suddenly, it receives:

> 25,000 login attempts.

The baseline makes the unusual increase easier to identify.

---

# Thresholds

A **threshold** is a defined level at which an action or investigation may be required.

### Example

An organization establishes a threshold:

> More than 10 failed login attempts from one account within 5 minutes requires investigation.

If the threshold is reached, security personnel may investigate.

---

# Trends

Security teams can examine metrics over time to identify trends.

### Example

| Month | Critical Vulnerabilities |
|---|---:|
| January | 25 |
| February | 20 |
| March | 15 |
| April | 8 |

The trend shows that the number of critical vulnerabilities is decreasing.

Trends can help determine whether security improvements are working.

---

# Why Metrics Matter

Cybersecurity metrics can help organizations:

1. Identify security weaknesses
2. Measure security performance
3. Track progress toward goals
4. Identify increasing risks
5. Prioritize security efforts
6. Support management decisions
7. Demonstrate compliance
8. Communicate security information

---

# Characteristics of Useful Metrics

A useful security metric should be:

- **Relevant** — related to the organization's security goals
- **Measurable** — based on information that can be collected
- **Consistent** — measured using the same approach over time
- **Understandable** — easy for the intended audience to interpret
- **Actionable** — can help support a decision or action

Avoid collecting measurements simply because they are easy to collect.

The metric should provide useful information.

# Example: Putting It All Together

An organization wants to reduce the risk of ransomware.

### Goal

Reduce the number of systems vulnerable to ransomware.

### KPI

Percentage of systems with current security patches.

### KRI

Number of critical vulnerabilities that remain unpatched.

### Baseline

Normally, the organization has approximately 10 unpatched critical vulnerabilities.

### Threshold

More than 25 unpatched critical vulnerabilities requires management attention.

### Trend

If the number increases from 10 → 15 → 25 → 40, the organization can see that its risk is increasing.

# Key Terms

| Term | Meaning |
|---|---|
| **Metric** | A measurable value used to evaluate something |
| **KPI** | Measures performance toward a goal |
| **KRI** | Measures or indicates risk |
| **Leading indicator** | Can warn about potential future problems |
| **Lagging indicator** | Measures something that already happened |
| **Baseline** | Normal or expected level used for comparison |
| **Threshold** | Level that may trigger an action or investigation |
| **Trend** | Direction of change over time |
