# Asset and Configuration Management

## 1. What Is an Asset?

An asset is anything valuable to an organization that needs protection.

Examples:
- Computers and servers
- Mobile devices
- Network equipment
- Software
- Databases
- Customer information
- Intellectual property
- Cloud resources

## 2. Asset Management

Asset management tracks organizational assets throughout their lifecycles.

A basic asset lifecycle:

1. Planning and acquisition
2. Deployment
3. Operation and maintenance
4. Review and updates
5. Retirement and disposal

Organizations should know what assets they own, where they are, who is responsible for them, and how important they are.

## 3. Asset Inventory

An asset inventory is a record of organizational assets.

It may include:
- Asset name
- Asset type
- Serial number or identifier
- Assigned owner
- Location
- Operating system
- Software version
- Classification
- Business importance
- Lifecycle status

An accurate inventory helps identify unknown or unmanaged systems.

## 4. Asset Ownership

An asset owner is responsible for an asset's appropriate use and protection.

Responsibilities may include:
- Determining classification
- Approving access
- Identifying protection requirements
- Reviewing asset use
- Ensuring proper disposal

Ownership does not necessarily mean the person physically possesses the asset.

## 5. End-of-Life and End-of-Support Systems

A system reaches end-of-life (EOL) when the manufacturer or provider ends its lifecycle support.

End-of-support may mean:
- No more security updates
- No more bug fixes
- No technical assistance
- Reduced compatibility

Unsupported systems can become security risks because newly discovered weaknesses may not receive fixes.

Organizations should:
- Identify unsupported assets.
- Evaluate their risk.
- Plan replacement or migration.
- Restrict access where appropriate.
- Document approved exceptions.

## 6. Configuration Management

Configuration management helps ensure systems maintain approved and secure settings.

Examples:
- Approved operating system settings
- Firewall configurations
- User permissions
- Application settings
- Security policies
- Network device configurations

## 7. Secure Configuration Baselines

A baseline is an approved starting configuration for a system.

A secure baseline may specify:
- Required security updates
- Approved software
- Account settings
- Logging requirements
- Firewall settings
- Access restrictions
- Unnecessary services to disable

Baselines help organizations maintain consistency.

## 8. Configuration Drift

Configuration drift occurs when a system's settings gradually differ from its approved baseline.

Possible causes:
- Unapproved changes
- Manual configuration
- Software updates
- Incorrect settings
- Inconsistent administration

Regular reviews and configuration monitoring help identify drift.

## 9. Change Management

Change management is the controlled process of making changes to systems and services.

A typical process includes:

1. Submit a change request.
2. Describe the reason for the change.
3. Assess security and operational risks.
4. Obtain required approval.
5. Test the change.
6. Implement the change.
7. Verify the results.
8. Document the outcome.

Emergency changes may follow a special approval process.

## 10. Why Documentation Matters

Documentation helps organizations:
- Track changes
- Identify responsible personnel
- Understand system configurations
- Investigate unexpected behavior
- Restore approved settings
- Demonstrate compliance

## Key Takeaways

- Assets include hardware, software, information, and services.
- Asset inventories help organizations know what they need to protect.
- Unsupported systems can create security risks.
- Secure baselines establish approved configurations.
- Configuration drift means settings have moved away from the approved baseline.
- Change management helps prevent unauthorized or poorly planned changes.
