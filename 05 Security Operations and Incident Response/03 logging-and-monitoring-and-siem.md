# Logging, Monitoring, and SIEM

## 1. What Is a Log?

A log is a recorded event generated by an operating system, application, network device, or security tool.

Logs help organizations understand what happened in their systems.

Common log sources:
- Operating systems
- Firewalls
- Routers
- Servers
- Applications
- Authentication systems
- Antivirus and endpoint security tools
- Cloud services

## 2. Common Log Information

A log entry may contain:
- Date and time
- Source device
- User or account
- Event description
- Source or destination IP address
- Event result
- Severity level

Accurate timestamps are important when investigating events across multiple systems.

## 3. Common Log Types

| Log type | What it records |
|---|---|
| Authentication | Login attempts and authentication events |
| System | Operating system events |
| Application | Application activity and errors |
| Firewall | Allowed and blocked network traffic |
| Audit | Security-relevant actions and changes |
| Network | Network connections and activity |

## 4. Security Monitoring

Security monitoring involves observing systems and networks for unusual or suspicious activity.

Examples:
- Repeated failed login attempts
- Unexpected account privilege changes
- Unusual network connections
- Malware alerts
- Unexpected changes to important files
- Unusual data transfers

Monitoring helps identify potential security incidents.

## 5. SIEM

SIEM stands for Security Information and Event Management.

A SIEM collects and analyzes security information from multiple sources.

Typical functions:
- Centralized log collection
- Event correlation
- Alert generation
- Searching and reporting
- Supporting investigations

Example:
A SIEM may correlate repeated failed logins with a successful login from an unusual location.

This combination may deserve investigation.

## 6. Event Correlation

Event correlation means connecting related events from different sources to identify a larger pattern.

Example:
1. A firewall records an unusual connection.
2. An endpoint tool reports suspicious activity.
3. An authentication system records an unexpected login.
4. A SIEM correlates the events and generates an alert.

One event may seem harmless by itself, but multiple related events may indicate a security concern.

## 7. Alert Severity

Security alerts may be ranked according to severity.

Common levels:
- Informational
- Low
- Medium
- High
- Critical

Severity can depend on:
- Potential impact
- Likelihood of harm
- Asset importance
- Whether the activity is ongoing
- Whether sensitive data is involved

## 8. False Positives and False Negatives

**False positive:** A security tool reports a threat when no actual threat exists.

**False negative:** A security tool fails to detect an actual threat.

Both are important:
- Too many false positives can overwhelm security teams.
- False negatives can allow threats to go unnoticed.

## 9. Log Protection

Logs can contain sensitive information and may be valuable during investigations.

Good practices:
- Restrict access to authorized personnel.
- Protect logs from unauthorized modification.
- Use reliable time synchronization.
- Retain logs according to policy and legal requirements.
- Review logging systems regularly.
- Protect centralized log storage.

## 10. SIEM vs. Log Management

| Log management | SIEM |
|---|---|
| Collects and stores logs | Collects and analyzes security events |
| Supports searching and retention | Supports correlation and security alerting |
| Focuses on log handling | Focuses on security visibility and detection |

## Key Takeaways

- Logs record system and security events.
- Monitoring looks for suspicious activity.
- SIEM centralizes and correlates security information.
- Correlation can reveal patterns that individual events do not show.
- False positives and false negatives are different detection errors.
- Logs should be protected against unauthorized access and changes.
